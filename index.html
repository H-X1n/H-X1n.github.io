01核心项目视频优选模型vmmax-v1

智能投放通过模型算法技术，在创编汰换、出价、预算、流量、素材生成等方面进行智能决策，旨在帮助广告主以更少的投入最大限度地提升广告投放效果，降低广告主投放广告的门槛，是电商商业投放重要的产品方向。 目前智能投放主要是基于规则和后验效果进行视频的选择和创编，缺少先验信息的利用和判断，导致基建冗余，故本期搭建了视频优选模型，对智能投放视频进行排序优选，进而带动智能投放收入增长。

  • 模型：
    Base model选择google/gemma-4-E4B-it——模型支持视觉、语言、音频输入
    模型最后一层token做avg pooling后接上Score head
    Score head 结构为：Linear(2560, 2048) -> GELU -> Dropout(0.1) -> Linear(2048, 1)
  • 数据：包含视频及视频对应的后验指标CTR，筛选视频曝光数eshow>1w
  • 模型输入：

02核心项目视频优选模型vmmax-v2

针对 v1 的问题，由端到端训练改为传统两阶段训练，并把 transtype（80/90）作为特征注入下游推荐模型：
1.基于业务指标训练一个多模态表征模型，表征模型输出多模态表征向量
2.表征向量作为内容特征进入下游推荐模型TREAD ，训练推荐模型
相比于传统内容向量来源于表征模型最后一层，TREAD将表征模型多层内容向量投影成固定维度的token与token化的商品侧特征以及task-query token做交互，通过task-query token对其余token的注意力分数进行剪枝，最后在兼顾计算量的同时提高了评测指标。

PROJECT 01实习项目

OnlineSoccer：流式足球视频 Caption 模型

直播进行到任意时刻都能回看提问：比如在第 30 分钟问「第 10 分钟发生了什么？」，模型依据已播出的画面，生成那一刻的解说描述（caption）。一场比赛超过 90 分钟，画面要一直累积在 VLM 的上下文里；项目把论文 OnlineSoccer 的因果时空压缩策略用到直播流上，画面边播边压缩，视觉 token 约少 32 倍。

  • 32×token 压缩
  • 422完整比赛
  • 12万+QA 模板
  • 8×A100 训练
流式推理
直播画面按时间顺序逐段压缩，追加进 VLM 上下文并持续累积，直到用户提问；模型依据累积的上下文，生成被问时刻的 caption。投影器是因果的，已输出的视觉 token 只依赖已经播出的画面。
压缩策略（论文）
以 Qwen2.5-VL-7B 为基座，插入论文提出的 Temporal Mamba Proj：先降宽并做 2×2 空间池化，再用 4 层因果 Mamba-3 + SwiGLU 沿时间扫描，最后通道打包、按 stride 选取输出。每 32 帧画面从 1,792 个视觉 token 压到 56 个（32×），调整 stride 不用重新训练。论文实验中，56 个 token 的 CIDEr 为 37.54，高于原生 1,792 个 token 的 34.62。
数据构建
覆盖 422 场完整比赛、12 万+ QA 模板与 3.2 万+ 固定 QA：问题指向比赛中已经播出的某一时刻，答案是那一刻的解说描述；按被问时刻距提问时刻的远近，分为 short / mid / long 三级记忆延迟。
训练策略
四阶段课程训练（视觉语言对齐 → 通用多模态 SFT → 足球领域适配 → 全场流式 QA），冻结视觉编码器、仅训练投影器与 LLM LoRA，8×A100 分布式训练。

PROJECT 02Agentic RL

长程中文购物 Agent 后训练：LoRA SFT + 多轮在线 GRPO

基于 ShopSimulator v2.1 搭建中文购物 Agent 的后训练与评测流水线：Qwen3.5-2B 先做 LoRA SFT，再用 veRL 做多轮在线 GRPO。在 200 题留出集上，strict success 从 0% 提升到 62.0%，平均 reward 从 −0.11 提升到 0.52。训练用终局规则 reward，不用 LLM-as-Judge；评测由代码硬校验和双 LLM 评审组成。

  • 62.0%strict success（基线 0%）
  • 0.52平均 reward（基线 −0.11）
  • 1,000条验收轨迹做 SFT
  • 1 张96GB GPU，约 110 s/步
数据
以 DeepSeek-V4.1-Flash 为 teacher，在模拟器中真实执行并采集 2,498 条轨迹；按终局结果严格验收后保留 1,026 条，选用 1,000 条（800 训练 / 200 验证），与 RL 训练集、评测集的 task_id 零重叠。
LoRA SFT
对 Qwen3.5-2B 做 LoRA SFT，只在 assistant 动作 token 上计算 loss，屏蔽用户指令与环境观测。strict success 从 0% 提升到 60.5%，模型学会了合法的工具调用、多步搜索和正确终止。
多轮在线 GRPO
在 veRL 0.8 上自研 AgentLoop 与工具适配层，从合并后的 SFT 模型出发做在线 GRPO：每题 rollout 4 条轨迹，8 个环境 worker 并行，单张 96GB GPU 平均约 110 s/步。第 100 步时 strict success 62.0%、买对率 62.5%，平均 reward 从 0.47 升到 0.52，主要减少了买错、循环和非法动作。
Reward 设计
只在终局给分，结果确定、可复现。品类和预算是硬门槛，品牌 / 型号 / 核心功能 / 关键规格按 0.35 / 0.25 / 0.25 / 0.15 加权：命中目标商品得 1.0，买到完全满足需求的替代品得 0.55，部分满足最多 0.25；买错、提前放弃、重复循环、超出步数分别给不同的负分。证据不足的样本标为 reward_valid=false，不当作有效的 0 分。
评测体系
用 DeepSeek-V4.1-Flash 从代码抽取的候选约束中选择并冻结 rubric，baseline / SFT / GRPO 三组共用，且不能新造约束字段；用 DeepSeek-V4-Pro 按搜索策略、候选利用、证据核验、决策质量、终止效率五个维度打 0/1/2 分，评审看不到 reward 和 gold 商品字段。结果分 reward、规则满足度、轨迹质量、效率四块报告，缺失和出错的题仍计入固定分母。

Paper No. 01Venue · WWWRank · CCF-ARole · 第一作者

WWW2027 在投UNDER REVIEW

TREAD: Inspectable Task-Query Reading of Frozen Multimodal Layer Representations for Advertising Response Prediction

第一作者 · 百度

  • WWW 2027 在投
  • CCF-A
  • 第一作者

视频广告要在同一素材上同时预估点击率（CTR）、转化率（CTCVR）与 5 秒播放率（Play5）。常见做法把视频内容压成一个向量，既看不出各任务依赖编码器的哪一层，也无法控制参与计算的内容 token 数量。TREAD 让三个任务 query 直接读取冻结多模态编码器的 21 个层级 token 和 1 个结构化特征 token（5 个商品字段 + 投放上下文 + 视频 URL + 价格），在一次自注意力中完成多任务读出。

  • 11/21保留 token · AUC 变化 <0.1%
  • -41%自注意力 FLOPs
  • +15.61%线上 GMV（20% 流量）

方法贡献

  • 把冻结多模态表征模型中不同层的 hidden state 分别投影成 token，与 1 个结构化特征 token、CTR / CTCVR / Play5 三个任务 query 一起送入同一个 8 头自注意力块，为每个任务保留一条可检查的「编码器深度 → 输出」路径。
  • 用训练集上的 query 注意力给内容 token 排序，推理前直接删掉低排名 token，不重新训练、不重新选模型；对照实验显示最后一层 L41 是必需 token，去掉后 CTR AUC 至少下降 8%。
  • 结构化特征 token 经 cross/deep 网络融合 5 个商品字段、投放上下文、视频 URL 与价格，使内容与业务特征在同一注意力归一化下交互。

实验结果

保留 11/21 个 token 时，三个任务 AUC 变化均小于 0.1%，自注意力 FLOPs 降低 41%，延迟从 1.96 ms 降到 1.59 ms；与单向量内容模型、EARec 适配模型、无内容模型相比，三个任务 AUC 均最高。商品字段全部替换为 UNK 时，CTR / CTCVR AUC 仅下降 1.3% / 2.8%（无内容模型为 17.8% / 18.4%），说明商品信息缺失时内容表示能兜底。线上 20% 流量 A/B：点击 +10.14%、转化 +15.90%、GMV +15.61%，曝光 +7.13%、CTR +2.81%、CTCVR +8.19%。

Paper No. 02Venue · CSCWDRank · CCF-CRole · 第一作者

CSCWD2027 在投UNDER REVIEW

Ranking Within Fixed Source Allocations: Controlled Mathematical Instruction Selection

第一作者

  • CSCWD 2027 在投
  • CCF-C
  • 第一作者

指令数据选择其实是两件事：哪些源问题拿到训练预算（源分配），以及同一源问题下哪几条记录被选中（记录排序）。常见的全局比较把两者混在一起，即使输入 token 上限相同，实际监督 token 与训练步数也可能不同。论文提出 source-controlled 评测协议：在完全相同的 source / type / token-length 单元格内配对「排序选出」与「均匀采样」的记录，让源配额、记录数、输入 token、监督 token 与训练步数全部对齐，把排序本身的价值单独测出来。

  • +1.66%严格匹配率（相对）
  • 22.4 万MetaMathQA 记录
  • 5 项配对对齐的预算维度

方法贡献

  • 把指令数据选择拆成源分配与记录排序两个可分离变量，提出在固定源配额下评估排序价值的协议。
  • 用配对单元格设计同时对齐源、类型与长度，并在三个子集构造 × 三个训练种子上重复实验，给出 question-bootstrap 置信区间。
  • 指出全局比较在近乎相同的输入预算下会产生不同的监督 token 总量，说明比较排序方法时必须同时报告源配额与实际监督量。

实验结果

在 223,553 条 MetaMathQA 记录与 Qwen2.5-1.5B 上，LESS 排序的平均严格参考答案匹配率为 79.731%，配对的均匀采样为 78.429%，相对提升 1.66%；三种构造与三个种子的均值均为正，去掉任一构造或种子后仍为正，条件 95% bootstrap 区间为 [0.000, 2.604] 个百分点。

FG2027 在投UNDER REVIEW

Beyond Shot and Group Counts: Support Allocation in Low-Shot Landmark Gesture Classification

第一作者

  • FG 2027 在投
  • CCF-C
  • 第一作者

小样本评测通常只报告支持样本数（K）和采集组数（U），但这两个数并不能确定支持记录在组间怎么分配——同样「5 shot × 2 组」，可以是 4+1，也可以是 3+2。论文把这一被忽略的分配变量单独拎出来，在 HaGRIDv2 关键点数据的 18 类手势上，枚举 K=5 的全部 7 种分配，并让每条记录的入选概率保持一致，从而只观察分配带来的差异。

  • +1.93 pp坐标特征 ridge 召回
  • +1.73 pp混合几何特征 ridge 召回
  • 7 种K=5 分配全枚举

方法贡献

  • 在 K=5 下枚举全部 7 种记录分配（U=1–5），以 U=2 的 4+1 vs 3+2 为主对照；随机化组位置并匹配每条记录的入选概率，使类别原型期望不变、只让支持集协方差与决策边界发生变化。
  • 同时给出 ridge 与 RBF SVM 两套分析，并用原型与协方差对照排除「支持集离散度」这一替代解释。
  • 用近似联合 95% 区间报告效应量，说明支持分配 q 应当成为小样本比较中必须对齐并报告的变量。

实验结果

把 4+1 重新分配为 3+2 后，坐标特征与混合几何特征的 ridge 召回分别提升 1.93 与 1.73 个百分点，近似联合 95% 区间为 [1.33, 2.52] 与 [1.14, 2.33]；三组分配的效应更小。在固定组数下该效应同样出现在 RBF SVM 分析中。

Paper No. 04Venue · CSCWDRank · CCF-CRole · 第一作者

CSCWD2027 在投UNDER REVIEW

OnlineSoccer: Compact Video Captioning with a Causal Spatiotemporal Projector

第一作者 · 咪咕视讯实习成果

  • CSCWD 2027 在投
  • CCF-C
  • 第一作者

给足球片段生成解说草稿时，每个片段都要占用一次语言模型的注意力计算与 KV 存储，稠密视觉前缀让这个成本很高。直接采样虽然缩短了序列，却让未采样的帧完全无法参与生成。OnlineSoccer 先把时序证据聚合再做输出选择：Temporal Mamba Proj 用降宽的因果状态空间模型逐时间单元更新，配合空间池化与通道打包压缩前缀；推理时只需调整输出 stride 就能改变视觉 token 预算，无需重新训练。

  • 112 vs 1,792视觉 token（约 16×）
  • 37.54CIDEr（56 token / stride-2）
  • 0.81%8× 压缩下的 CIDEr 波动

方法贡献

  • 提出 Temporal Mamba Proj：每个时间单元更新一个单向状态空间模型，让保留下来的视觉输出能携带前面被省略单元的信息，而不是简单丢帧。
  • 用空间池化与通道打包进一步压缩投影器宽度和输出 token 数，把 1,792 个原生视觉 token 降到 112 个。
  • 把「保留多少 token」变成推理期参数：同一个 checkpoint 通过推理期 stride 支持不同前缀预算。

实验结果

在 SoccerNet Caption（MatchTime 校正）的居中片段上，不做采样的接口只用 112 个视觉 token 就达到 37.36 CIDEr，比稠密基线相对提升 7.91%；stride-2 只用 56 个 token，CIDEr 37.54，同等推理预算下比池化策略高 19.55%。纯时序扫描中前缀缩小 8 倍，CIDEr 波动仅为 stride-1 得分的 0.81%，而直接采样下降 14.36%。
